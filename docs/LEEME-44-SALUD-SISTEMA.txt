📌 CÓMO CONECTAR GITHUB (la otra tarjeta "Caído · Sin token")
------------------------------------------------------------------
GitHub no tiene botón de conexión: se configura con un token en el
.env del SERVIDOR (Hostinger):
  1. GitHub → Settings → Developer settings → Personal access tokens
     → Tokens (classic) → Generate new token (classic).
     Sin marcar ningún scope (el chequeo solo identifica la cuenta);
     caducidad a tu gusto.
  2. Copia el token (ghp_…) y en el .env de tu servidor añade:
        GITHUB_TOKEN=ghp_tu_token_aqui
  3. pm2 restart … (o redeploy) → "Verificar ahora" en el panel.
  4. La tarjeta debe decir "Operativo · Autenticado como tu-usuario".

LA CAUSA RAÍZ (encontrada y confirmada)
---------------------------------------
En la actualización del 18-oct (app.js v5) metimos una ruta de salud
DEFENSIVA dentro de app.js, registrada ANTES del montaje /api/admin
para curar un 500 que había en ese entonces:

    app.get('/api/admin/salud', ...)      ← v5, básica (versión + conteos)
    ...
    app.use('/api/admin', adminRoutes)    ← tu endpoint REAL de salud

Express responde con la PRIMERA coincidencia registrada. Resultado: la
ruta básica v5 TAPA el endpoint real de tu admin.routes.js. El panel
sí recibe un 200 (por eso la cabecera pinta la versión 1.0.0), pero la
respuesta no trae los servicios → las tarjetas quedan vacías.

LA SOLUCIÓN (v6)
----------------
En vez de "quitare la defensiva", la convertimos en el motor DEFINITIVO
de salud: ahora la ruta /api/admin/salud VERIFICA DE VERDAD cada
servicio y responde la información completa que el panel necesita.

  NUEVO archivo:  src/salud-admin.js   ← el motor (autocontenido)
  ACTUALIZADO:    src/app.js           ← llama al motor (con respaldo)

Qué verifica cada tarjeta (con llamada real, latencia y límite de 4 s):

  ⚙️ Node.js    versión, tiempo activo, memoria del proceso
  🗄️ MongoDB    conexión + ping real a la BD (latencia en ms)
  ☁️ Cloudinary credenciales del .env + api.ping() del SDK
  💳 Stripe     STRIPE_SECRET_KEY + consulta de balance
  📣 Meta       token de página + GET graph.facebook.com/me
  🐙 GitHub     GITHUB_TOKEN + GET api.github.com/user

Estados posibles por servicio: operativo · con-avisos · error ·
sin-configurar. El estado global: operativo / degradado (1 error) /
critico (2+ errores o BD caída).

Garantías de seguridad:
  - NUNCA responde 500 (todo en try/catch + respuesta de emergencia).
  - NO expone claves ni tokens: solo estados, latencias y mensajes
    de error truncados.
  - Caché de 30 s en memoria: abrir el panel no martilla las APIs
    externas. El botón "Verificar ahora" (o ?fresh=1) fuerza una
    re-verificación al instante.
  - Si 2 peticiones llegan a la vez, comparten UNA sola verificación.
  - Servicios sin configurar en el .env se muestran como
    "sin-configurar" (no como caídos): nada de alarmas falsas.
  - La respuesta trae la forma en VARIOS formatos (servicios[],
    sistemas[], checks{}, estadoServicios{} + todos los campos de
    antes) para que tu panel la pinte sin cambios.
  - Tu admin.routes.js puede quedarse como está: si tiene su propia
    ruta /salud, esta le gana por orden y le sirve de respaldo.
